# 反馈 — 等用户报词后更新词汇掌握状态

**本技能必须在用户给出反馈之后才能执行。流程：先把本轮目标词单（含释义）端给用户 → 停下等待用户逐词回复"会/不会" → 拿到用户反馈后，再原样传入执行。在没有收到用户反馈之前，禁止调用本技能、禁止自己猜评级。**

## 触发前提（硬性要求）

1. 上一步（更定频率）完成后，把本轮目标词单连同释义列给用户。
2. **停下来等用户回复**，例如用户说"ridiculous 不会、rough 会、tale 会"。
3. 只有收到这样的反馈后，才执行下面的命令；用户没回、只回了一部分，都照实际收到的执行。

## 唯一的动作

用户会给一批"词 + 评级"。原样传入：

```bash
# 在仓库 skills/engstory-domain/ 目录下执行
python scripts/feedback.py --words "abandon 会, coffin 不会" --vocab "<词库路径>"
```

- 词和评级用空格分隔，词条之间用逗号分隔。
- **必须使用「检索」返回的词条 key**：单义词如 `castle 会`，多义词如 `blue|忧伤 不会`。
- 只写 `blue 会` 且它有多个释义时，系统会提示歧义并拒绝更新，绝不会一并修改所有意思。
- 评级只认两个最常用的（其余可选）：
  - **会 / 会了 / 记住了** → Good（记得牢，下次间隔拉长）
  - **不会 / 忘了** → Again（忘了，难度↑，很快再见）
  - 可选：**勉强**（Hard）、**很熟**（Easy）

## 端上来的样子（原样呈现即可）

```
已更新 2 个词条的记忆状态：
  abandon  [Good]  下次 5 天后  难度 2.118
  coffin   [Again] 下次 约 10 分钟后  难度 5.118
词库没有，跳过：seek
```

**不需要解释，不需要加工，直接呈现。**

## 它做了什么（自动）

- 每个词条维护一套 FSRS 记忆状态（难度、稳定性、下次到期），由 py-fsrs 算法计算（MIT 开源，行业标杆间隔重复算法）
- 反馈一次，状态更新一次；"不会"的词难度上升、下次到期只剩几分钟，下一轮检索**必现**在第一位，"会"的词间隔拉长、沉到后面休息
- 词条没有记忆状态时自动按"新卡"起步（立即到期）
- **不碰** picks/uses/texts 那些统计字段（那是检索/更定频率的事）

## 边界

- 只更新记忆状态。不检索（那是 **检索** 技能）、不更定使用频率（那是 **更定频率** 技能）。
- 词库默认 `/workspace/vocab.json`，环境变量 `ENGSTORY_VOCAB` 可改。
