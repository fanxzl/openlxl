# 检索 — 从词库拿词汇（触发即执行）

**本技能触发时，立即从词库检索选词，把结果端给用户。不要询问、不要先介绍命令、不要问要几个——直接跑，跑完把输出原样呈现。**

## 唯一的动作

```powershell
# 在仓库 skills/engstory-domain/ 目录下执行
python "scripts/pick.py" --vocab "<词库路径>"
```

立刻运行，把终端输出端给用户。无需前置条件，无需参数，无需确认。

- 用户如果明确说了要几个（"给 5 个""来 12 个"）→ 加 `-n 5` / `-n 12` 再跑。
- 其余情况一律用默认（7 个），不要多问。

## 端上来的样子（这就是交付物，原样呈现即可）

```
本次选词 7 个（按到期/遗忘排序，越靠前越该练）：
  crypt       地下室    [词条 crypt] [遗忘分 48.2] [到期 已逾期] [检索 3 次，上次 7天前；已用 1 次 / 1 篇]
  coffin      棺材      [词条 coffin] [遗忘分 45.7] [到期 已逾期] [检索 3 次，上次 7天前；已用 1 次 / 1 篇]
  rapid       迅速的    [词条 rapid] [遗忘分 30.4] [到期 约 1 分钟后] [检索 2 次，上次 10分钟前；已用 0 次 / 0 篇]
  novel       小说      [词条 novel] [遗忘分 30.0] [到期 新词] [检索 3 次，上次 7天前；已用 1 次 / 1 篇]
  blue        蓝色      [词条 blue|蓝色] [遗忘分 30.0] [到期 新词] [检索 1 次，上次 昨天；已用 0 次 / 0 篇]
  blue        忧伤      [词条 blue|忧伤] [遗忘分 30.0] [到期 新词] [检索 0 次，上次 从未；已用 0 次 / 0 篇]
  tale        故事      [词条 tale|故事] [遗忘分 5.4] [到期 明天] [检索 2 次，上次 今天；已用 1 次 / 1 篇]
  ...
```

每个词后面的数据就是选它的理由：
- **词条 key** — 后续 `mark.py --words` 与 `feedback.py --words` 必须原样传递的独立标识；单义词如 `castle`，多义词如 `blue|蓝色`、`blue|忧伤`
- **到期** — 这个词下一次该复习的时间点，用自然语言表达：`新词`（还没反馈过）/ `已逾期`（早该复习了）/ `约 X 分钟后`（学习中）/ `今天`/`明天`/`N 天后`（复习间隔中）
- **遗忘分** — FSRS 记忆状态算出的遗忘程度（0~100+），**同到期时间下越高越接近遗忘、越该练**；未反馈新词默认=30
- **检索 N 次 / 上次 X** — 这个词被挑出来过几次、上次是什么时候
- **已用 N 次 / N 篇** — 实际在文本里出现过几次、分布在几篇里

**多义词注意**：同一单词的不同意思（如 `blue 蓝色`、`blue 忧伤`）是**独立词条**，会分开展示、各有各的频次——生成时用哪个意思，就按哪个词条的释义来写。

用户拿到这份词单即可当写作素材用。**不需要解释，不需要加工，直接呈现。**

## 检索依据（谁排在前面）

按 **FSRS 到期驱动**（Anki 同款间隔重复算法）四队列排序，越靠前越该练：

1. **学习中/重学中的词**——上次报过「不会」（或还在学习步骤里）的词，到期时间很近，下一轮无论隔多久都最先被捞回来
2. **已逾期的复习词**——早就该复习了，按逾期先后排列
3. **没反馈过的新词**——默认遗忘分 30，排在已经练过的词之后，保证新词持续流入
4. **未到期的复习词**——还没到复习时间，按到期先后补位（练习轮次不足 7 个时才会用到它们）

**「不会」的词下一轮必现**：反馈为「不会」后词会回到学习/重学队列、到期只剩几分钟——所以无论下一轮是 10 分钟后还是 3 天后调用，它都排在最前面。这是算法保证，不是用户要操心的。

## 边界

- 只检索。写文章、定写作规范、存文件——都是调用方/其他技能的事。
- **不改记忆状态**。词的难度/稳定性/到期由 **反馈** 技能（按用户报会/不会）更新；`uses/texts/last_use` 由 **更定频率** 技能更新。
- 词库默认 `/workspace/vocab.json`，环境变量 `ENGSTORY_VOCAB` 可改。词库没准备好时直接报错提示，不要自己造词。
